# USD stable balance

The `stable-balance` branch adds voluntary conversions between the selected mint's existing Cashu ecash and mainnet USDB on Spark. Open **Convert** in the top navigation. The wallet balance card has compact, animated **BTC / USD** tabs that also support horizontal touch swipes, mouse drags and trackpad swipes. Both amounts can be tapped to show or hide balances, and Dollar holdings show their estimated equivalent in the selected display currency. The conversion opens in the selected balance’s direction; saved operations retain their recorded direction. Enter an amount to move from Bitcoin or Dollar, or choose 25%, 50%, 75%, or 100% of that balance. The entry screen fetches the provider’s minimum in the selected source currency, shows the available range, and disables below-minimum percentages. After a 250 ms typing pause, it validates a live quote and fees before enabling Review. The initial market-rate estimate is replaced with the live result. Preview quotes never create history entries, allocate blinding outputs, save a conversion, or send funds. Direction/input changes abort stale checks. Checks wait for the SDK/provider response without an app-imposed time limit. Changing the amount/direction or leaving the screen discards obsolete results; elapsed time alone does not cancel a valid request. If the provider reports a failure, Review stays disabled with a retry action. Asset metadata is verified once per SDK connection, conversion limits are cached for 20 seconds, and checked inputs are reused for 15 seconds. Read-only checks do not wait behind the background balance lock. A fee-inclusive minimum recommendation is shown when known. Bitcoin-to-Dollar Review reuses previews younger than 15 seconds without repeating pricing calls, with a new operation ID and current recovery snapshot. Older previews are refreshed, and Dollar-to-Bitcoin Review still prepares the blinded mint outputs. Quotes reduce the destination amount when needed to leave room for fees within the selected source amount (bounded interpolation and bisection handle stepped fees, retaining the best valid quote; at most 12 attempts, stopping early when the debit fits within 1% of the selected budget or the output interval cannot improve; no payment is made during quoting). Confirm only after seeing the actual receive amount and total. Dollar holdings are shown separately from the approximate fiat value of ecash sats. The normal UI uses Bitcoin and Dollar labels; provider and asset identifiers stay in the implementation.

USDB is a stablecoin, not a bank USD balance. Its value depends on its issuer maintaining the peg. This integration uses the existing wallet-derived Spark seed and existing Breez credentials; no separate account or funding balance is required.

## Transfer paths

- **Sats → USD:** quote a manual self-conversion to USDB; request an exact Lightning funding invoice from Spark; review the maximum ecash debit (including mint input fees and fee reserve); pay that invoice once from the selected mint; sync Spark; recheck the conversion cost against the approved funding; convert to USDB.
- **USD → Sats:** create a Cashu mint Lightning invoice for the selected output; quote and confirm a USDB-to-Bitcoin payment to that invoice; claim and verify the resulting ecash proofs before marking complete. The displayed USD debit is an estimate. The SDK enforces its conversion slippage policy; its public API does not expose an independent hard source-token debit cap.

The SDK is `@breeztech/breez-sdk-spark` 0.28.x. Automatic Stable Balance activation is deliberately unused: enabling it converts incoming or excess sats rather than just the user-selected amount. The verified mainnet USDB identity is `btkn1xgrvjwey5ngcagvap2dzzvsy4uk8ua9x69k82dwvt5e7ef9drm9qztux87`, with six decimal places. Token metadata is verified before displaying holdings or quoting. Minimum amounts come from the SDK and are refreshed from any newer provider minimum rejection. When a cached market-price estimate undersizes the conversion (for example 723 sats versus an 800-sat provider minimum), quote sizing uses the provider’s reported input to correct the output while keeping the selected source budget. Maximum conversion slippage is 10 basis points (0.1%).

## Recovery and concurrency

Conversion records live in the encrypted Rust wallet, alongside existing Cashu proofs and transaction history. Decimal amounts and SDK bigint quotes are stored without floating point rounding. At most one operation is active per wallet. A shared frontend lock serializes conversions and background sweeps; native guards also reject sweeps and new onchain send funding while a conversion is active. Missing/locked wallet state fails closed.

Quotes expire after 60 seconds and can be cancelled before funding. Leaving the Transfer funds page preserves the saved operation. Reopening Convert loads it again. A funded conversion can continue without paying its funding invoice again, or quote a return to ecash that the user confirms separately. Return fees can leave a small Spark BTC remainder; the existing sweep handles eligible BTC remainders after the operation completes.

AMM/token conversions omit the SDK idempotency key: Breez rejects a key on a token transfer leg before executing the conversion. Plain BTC funding returns retain their supported key. New conversion attempts persist request version 1 before calling the SDK. For the original version-0 attempts, **Resume → Check progress** restores the rejected conversion to funded (sats → USD) or quoted (USD → sats), preserving its existing funding. Only an unrecorded version-0 AMM attempt can use this repair; new ambiguous attempts remain blocked from replay. An expired reverse quote can be cancelled and recreated.

An ambiguous conversion or return-payment timeout is never blindly resent. **Check progress** reconciles its saved payment ID or unique paid mint quote. A completed USDB self-conversion can be recovered from a single matching new receipt; multiple matches remain unresolved. **Recover transfer** calls the SDK's refund API. Only an explicit provider refund releases that conversion's reservation. If no authoritative result exists, the operation remains saved and blocks sweeps; it requires later provider/mint status resolution rather than a potentially duplicate spend.

Cashu funding and minting retain their existing transaction history records. Unpaid mint quotes requested during review may remain pending in history until the mint reports their expiry. The conversion journal preserves the cross-system operation separately.

## Verification

Run `npm run test:payments`, `npm run build`, `cargo test -p ecash-wallet --lib`, and `cargo check -p bitnotes --lib` from their applicable directories. Tests use mocked Spark/mint boundaries and cover both directions, explicit confirmation, debit caps, changed prices, timeouts without duplicates, refund recovery, token identity validation, and old encrypted-wallet schema compatibility. Mobile UI was exercised in isolated Chrome with mocked payment services. No real-money conversion has been performed as part of development; mainnet/provider availability still needs a small user-controlled device test.

The open transfer page automatically reconciles the saved payment with exponential backoff (1–15 seconds), pauses network checks while hidden, and stops when the page closes or an explicit failure occurs. Transport errors after submission preserve the original cause as expandable transfer details; status checks resolve the original payment and never repeat funding or the conversion send. The animated success overlay appears only after a completed conversion/receipt. Cashu settlement must explicitly report Success before funding or returned/received ecash is marked settled.
